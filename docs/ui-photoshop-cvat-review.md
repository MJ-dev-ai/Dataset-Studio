# Dataset Studio UI 검토 — Photoshop + CVAT

2026-10-23. UTF-8. 메인 편집 화면과 사용자 정의 대화상자 10종을 함께 검토했다.

## 결론

현재 초안의 가장 큰 문제는 외형보다 **각 영역의 역할과 상태가 겹치거나 서로 어긋나는 것**이었다. 같은 도구명과 클래스 입력이 반복되고, 보조 작업도 주요 적용 버튼과 같은 색을 사용했다. 파일을 열면 도구 안내가 파일 경로로 바뀌고, 창을 조절하면 사용자가 바꾼 패널 폭이 초기 비율로 돌아갔다. 대화상자는 동일한 종류의 입력인데도 폭·버튼·실행 가능 상태가 달랐다.

이번에는 Photoshop의 도구 중심 편집 구조와 CVAT의 객체 중심 라벨링 구조를 기존 PySide6 앱에 맞게 결합했다. 색상만 바꾸거나 웹 UI를 그대로 옮긴 작업이 아니다. 이미지·라벨·MapSet·worker의 기존 역할은 유지했다.

## 비교 근거와 채택 원칙

Photoshop은 **Adobe 공식 문서의 작업 공간 설명과 이미지 크기 대화상자 설명**을 확인했다. Photoshop 설치본 실행·비공개 코드 분석은 하지 않았다. CVAT는 공식 문서와 이전에 별도 클론한 커밋 `641073751e9a25790e2a26e18f8068d8f74f1be8`의 UI·선택·이력 소스를 참고했다. PhotoCraft와 Adobe Photoshop은 별개의 참고 대상이다.

| 영역 | Photoshop에서 참고한 점 | CVAT에서 참고한 점 | Dataset Studio 판단 |
|---|---|---|---|
| 상단 옵션바 | 현재 도구에 해당하는 설정을 표시 | 도구 선택 및 그리기 절차와 설정 연결 | 도구명·현재 설정·적용 명령만 상단에 두고 긴 도움말은 우측으로 이동 |
| 왼쪽 | 도구와 작업 자료를 구분하고 패널을 묶음 | 도형별 진입 도구와 단축키 안내 | 도구 막대 유지, 데이터셋과 패치 보관함을 리소스 탭으로 구성 |
| 오른쪽 | 현재 작업을 확인·수정하는 상세 패널 | 객체 목록과 객체 속성·표시 상태 연결 | 합성 시 위치·회전·소스, 라벨링 시 객체 목록·클래스·좌표 표시 |
| 작업 표면 | 문서 창이 작업의 중심 | 이미지와 객체의 선택 상태가 중심 | 빈 로그를 기본으로 접고 파일·크기·확대율·객체 수를 문서 상단에 고정 |
| 대화상자 | 입력 단위·원본/변경 값·미리보기·확정의 구분 | 반복 객체 편집은 캔버스/패널 안에서 처리 | 반복 라벨 생성은 패널에서, 일괄 설정·내보내기는 대화상자에서 처리 |

위 표의 Dataset Studio 열은 공식 제품의 명세가 아니라 이번 코드와 화면 검토를 바탕으로 한 적용 판단이다. Photoshop의 레이어 기반 비파괴 편집이나 CVAT의 서버·협업 기능까지 구현했다는 뜻은 아니다.

전체 번역 작업은 아니다. 주요 메뉴·도구·대화상자 설명을 한국어로 정리했으며 MapSet, YOLO, 합성 모드 이름 등 처리와 연결된 용어는 유지했다.

후속 단축키 개선: 시작 시 캔버스에 포커스를 지정하고, B/M/W/J 등의 도구 전환 키와 N, Shift+L/J를 편집 창 전체에서 처리한다. 좌우 목록·버튼·읽기 전용 로그에서도 전환 후 캔버스로 포커스를 옮긴다. 편집 가능한 텍스트·숫자 입력, 열린 메뉴/콤보 팝업, 별도 대화상자의 키는 가로채지 않는다. 방향키·Delete·Tab 등 작업별 키의 범위는 기존대로 유지한다.

실제 offscreen Qt 렌더링에서 확인한 크기다. 운영체제 제목 표시줄은 캡처에 포함하지 않았다.

공통 규칙은 `ui/themes.py`의 `configure_dialog`에 모았다. 여백과 버튼 역할을 지정하는 UI 함수이며 저장·취소·worker 실행을 대신 소유하지 않는다. 보조 버튼의 자동 기본 버튼 동작을 끄고 확정 버튼을 명확히 지정했다. 각 대화상자의 기존 accept/reject 흐름은 유지한다.

### UI 검토에서 발견한 실제 동작 오류

- **일괄 전처리의 비율 유지 체크박스가 치수 변경에 연결되지 않았다.** 너비/높이를 바꿀 때 원본 비율로 다른 값을 갱신하도록 수정했다. 잠금을 풀면 독립 입력이 가능하다.
- **사용하지 않는 전처리 옵션의 입력도 활성화돼 있었다.** 각 항목의 사용 여부에 맞춰 입력 활성 상태를 연결했다.
- **맵을 하나도 선택하지 않은 상태에서 확인을 눌러도 아무 반응이 없었다.** 버튼을 비활성화하고 필요한 조건을 표시한다.
- **증강 창이 데이터가 없는데도 Designer 예시 예상 수량을 보여줬다.** 초기 상태에서 실제 0개 계산으로 갱신하고 대상 이미지가 없으면 생성을 비활성화한다.
- **이미지를 열 때 파일 경로가 도구 안내를 덮어썼다.** 문서 정보와 도구 안내의 갱신 책임을 분리했다.
- 회전/밝기의 미리보기를 끄면 임시 화면만 원본으로 돌아가고 입력값은 남는다. 다시 켜면 같은 설정을 재표시한다. 취소는 픽셀을 바꾸지 않는다.

## 검증과 범위

- UI·테마·라벨링·도구·합성·패치·healing 관련 테스트 **112개 통과, 기존 비호환 테스트 1개 제외**.
- 마지막 패널 표시 보정 후 UI 동작 검사 **10개 재실행 통과**. 112개에 포함된 검사이며 합산하지 않는다.
- 제외: 기존 `test_fast_healing_preview_uses_lightweight_composite`는 현재 지원하지 않는 `fast_preview=True` 인자를 요구한다.
- UI 검사는 실제 Qt 위젯으로 입력·미리보기 토글·취소·비율 유지·확정 가능 조건·로그 토글·패널 폭 유지·증강 결과 탭 전환을 확인한다. 스크린샷은 별도로 한글 표시와 배치를 검토했다.
- 전체 저장소 테스트 통과를 주장하지 않는다. 기존 구형 PyQt6/학습 의존성 관련 수집 오류는 이번 UI 작업 범위 밖이다.
- 네이티브 파일 선택기·운영체제 메시지 상자의 배치는 OS에 맡긴다. 10종의 사용자 정의 대화상자를 검토한 것이며 모든 시스템 대화상자를 재설계한 것은 아니다.

## 다음 단계로 남는 설계 과제

이번에 구현했다고 주장하지 않는 항목이다.

1. **작업별 워크스페이스 저장**: 현재는 실행 중 사용자가 조절한 폭을 보존한다. 종료 후 복원, 합성/라벨링별 프리셋 저장은 별도 설계가 필요하다.
2. **객체가 많은 장면**: CVAT식 필터·검색·다중 선택·잠금이 도움이 된다. 다중 편집은 객체 모델·이력·저장과 함께 정의해야 한다.
3. **완전한 키보드/스크린리더 흐름**: 현재 입력창 키 보호와 일부 접근성 이름은 있지만 모든 대화상자의 탭 순서와 보조 기술 사용성 검증은 남아 있다.
4. **대용량 이미지 변형 미리보기**: 회전/밝기 대화상자의 기존 변형 계산 경로는 동기식이다. 패치/healing과 달리 큰 이미지에서의 취소 가능한 비동기 처리는 후속 성능 과제다.
5. **고해상도 모니터와 운영체제 입력기**: offscreen 캡처만으로 150%/200% 배율, 멀티모니터, 실제 한글 조합 입력의 모든 상태를 보장할 수 없다.
6. **저장 용어의 세분화**: 이미지·라벨·프로젝트가 서로 다른 저장 단위를 가진다. 이번에 버튼 이름을 명확히 했지만 통합 저장 상태와 저장 지점 이력은 별도 제품 결정이 필요하다.
