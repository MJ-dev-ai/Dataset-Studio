PhotoCraft를 `C:/Users/tnsmi/Downloads/photocraft-analysis`에 별도 클론했다. 검토 기준 커밋은 `ff4738810134d7f7e68b49f2e4f231b686282ff3`이다. Dataset Studio의 변경 전 기준은 `e0dd6612c670a185e925b439e7c5a71333d52608`이다. 기존 사용자 변경 사항인 런타임 로그는 보존했다. PhotoCraft의 소스는 수정하지 않았다.

## 결과물 품질에서 수정한 문제

### 1. Poisson 합성 위치가 미리보기와 다름

기존 코드는 전체 패치의 중심을 `seamlessClone`에 전달했지만 OpenCV의 일반 Clone은 선택 마스크의 유효 경계 상자를 중심으로 배치한다. 마스크가 비대칭이면 최종 결함이 미리보기와 다른 곳으로 이동했다.

48×48 패치의 한쪽에 마스크와 밝은 특징점을 만든 재현 예제에서 예상 좌표는 `(x=32, y=43)`인데 기존 결과는 `(42,48)`이었다. 수정 후 NORMAL/MIXED 모두 `(32,43)`이다. 선택 영역 밖은 대상 이미지와 정확히 일치한다. 이는 라벨과 결함 위치의 불일치도 줄이는 수정이다. 라벨 생성 자체의 정확도 전체를 검증했다는 의미는 아니다.

- `service/editing_service.py`: 전체 패치 중심을 명시적인 배치 기준으로 유지하고 마스크 경계 상자를 반영해 OpenCV 중심 좌표를 보정한다. 패치 경계의 마스크가 사라지지 않도록 패딩하고, 반환 시 마스크 밖 픽셀을 보존한다.
- 그림: `perf/blend-alignment.png`. 붉은 십자가가 목표 위치다.

### 2. 회전한 결함 가장자리에 검은 띠가 생김

기존에는 패치 RGB를 검은 배경과 함께 선형 보간하고 마스크는 최근접 보간했다. 선택된 경계 픽셀에도 검은 배경색이 섞였다.

- `tools/patch_tools.py`: 색상×마스크와 마스크 가중치를 같이 보간한 후 색상을 복원한다. 기존 이진 마스크 계약과 배치 좌표는 유지한다.
- 균일한 값 200인 선택 영역을 1.3배·27도로 변형한 예제에서 선택된 경계의 최솟값은 기존 54, 수정 후 200이다. 회색 및 3채널 이미지로 확인했다.
- 그림: `perf/transform-edge.png`.
- 이것은 경계 색 오염을 고친 것이다. soft alpha, 원근 변환, normal map 방향 성분 변환까지 구현한 것은 아니다.

### 3. 단일 이미지 채우기의 선택 범위·불투명도

MapSet 서비스가 처리하지 않는 fallback 경로에서 기존 선택을 전체 선택으로 바꾸고 불투명도를 무시하던 문제를 수정했다. 기존 선택 밖은 보존하고, 상단에서 지정한 불투명도가 실제 채우기에 반영되도록 했다.

## 툴 조작과 단축키

도구 키는 캔버스에 포커스가 있을 때 동작한다. 왼쪽 도구 선택 후에는 포커스를 캔버스로 돌린다. 클래스명·숫자 입력창에서는 입력과 텍스트 Undo가 우선한다.

| 키 / 조작 | 동작 |
|---|---|
| V 또는 H | 이동 / 보기 |
| Space + 왼쪽 드래그 | 현재 도구를 유지한 임시 이동. 키를 놓거나 포커스를 잃으면 해제 |
| M / L / P | 사각형 / 올가미 / 다각형 선택 |
| Shift+L | 올가미와 다각형 전환 |
| Shift / Alt / Shift+Alt + 선택 | 추가 / 빼기 / 교집합 |
| 다각형에서 Enter / Backspace | 완료 / 마지막 점 제거 |
| B / J / E / G | 브러시 / 복원 브러시 / 지우개 / 채우기 |
| Alt+클릭 | 복원 소스 지정. 기존 Ctrl+클릭도 유지 |
| [ / ] | 브러시 크기 감소 / 증가. 상단 숫자와 동기화 |
| K / Shift+J | 패치 선택 / 복원·패치 전환 |
| 패치에서 방향키 / Shift+방향키 | 1픽셀 / 10픽셀 이동 |
| 패치에서 Enter | 현재 선택한 합성 방식으로 적용 |
| 패치에서 Esc | 임시 패치 배치 취소 |
| W | 바운딩 박스 도구 |
| Ctrl+A / Ctrl+D | 전체 선택 / 선택 해제 |
| Ctrl+0 / Ctrl+1 | 화면 맞춤 / 100% |
| Ctrl+T | 기존 패치 배치가 있으면 패치 도구로 복귀 |

P/K/W는 Dataset Studio에 맞춘 배정이며 Photoshop과 완전히 동일한 매핑은 아니다. Ctrl+T는 일반 레이어의 자유 변형 기능을 새로 만든 것이 아니다. 채우기 후 자동으로 Move로 돌아가던 동작도 제거했다. 마우스로 진행 중인 브러시·선택 제스처는 단축키로 중간에 버리지 않도록 보호한다. 임시 결과만 표시하는 힐링 획은 Esc로 안전하게 취소할 수 있다.

## UI에서 확인한 원인과 반영한 구조

기존 코드의 `property_page_map`은 모든 도구를 동일한 정보 페이지로 연결했다. 정밀 패치 입력을 상단으로 옮긴 뒤 오른쪽의 관련 그룹은 숨기고, 선택 옵션 바에 저장·라벨·ROI 작업 버튼을 계속 추가하고 있었다. 따라서 상단은 길어지고 오른쪽은 현재 작업과 관계없는 카드가 보였다.

- **왼쪽:** 도구 선택에 집중. 기존에 직접 접근하기 어려웠던 패치·바운딩 박스 버튼 추가. 메뉴와 선택 체크 상태 동기화.
- **상단:** 도구명, 빠른 조작, 적용. 중복 도구 선택 버튼을 숨기고 선택 바의 데이터 관리 작업은 오른쪽으로 이동. 도구 옵션 dock의 별도 제목 줄 제거.
- **오른쪽:** 패치에서는 좌표·각도·크기와 합성 상태를 우선 표시. 선택·라벨 도구에서는 라벨·ROI 작업 표시. 다른 도구에서 관련 없는 그룹 숨김. 정밀 입력이 잘리지 않도록 최소 폭 조정.
- 상단과 오른쪽에 같은 현재 도구명을 표시. 선택 크기 및 패치 배치 상태를 실제 캔버스/도구 상태와 연결.
- 기존 `Confirm`은 색 보정 없는 Hard Paste였으므로 버튼을 **단순 붙여넣기**로 구분했다. Enter는 선택한 합성 방식인 Apply Blend에 연결했다.
- 한글 툴팁과 조작 안내 추가. 검증 화면은 맑은 고딕을 로드하여 한글 표시를 확인했다. 전체 메뉴 번역 작업은 범위에 포함하지 않았다.

화면 자료: `perf/ui-patch.png`, `perf/ui-polygon.png`, `perf/ui-healing_brush.png`, `perf/ui-bbox.png`. 합성 테스트 이미지로 렌더링했으며 실제 사용자 데이터는 사용하지 않았다.

## 응답성 관련 변경과 측정의 해석

다음은 **Dataset Studio의 변경 전후**만 비교한 CPU/Qt 함수 측정이다. PhotoCraft와의 ms 비교나 실제 화면 FPS 측정이 아니다. 한 번 예열 후 5회 측정한 중앙값이며 원시 샘플은 `perf/before.json`, `perf/after.json`에 있다.

| 4000×3000 입력 | 변경 전 | 변경 후 | 적용한 변경 |
|---|---:|---:|---|
| 밝기/대비 처리 | 99.85ms | 2.25ms | 256값 LUT로 동일한 float32·클리핑·절삭 결과 유지 |
| Qt 변환 포함 보정 미리보기 경로 | 125.99ms | 30.20ms | LUT와 중복 복사 제거 |
| 1픽셀 변경 이력 계산 | 131.41ms | 21.43ms | RGBA 픽셀 단위 비교, 좌표 전체 목록 생성 제거 |
| 동일 공유 이미지 이력 비교 | 121.83ms | 0.002ms | Qt cacheKey가 같은 경우 즉시 반환 |
| 짧은 브러시 스트로크 서비스 | 14.54ms | 3.49ms | 합성을 스트로크 경계 영역에 한정 |

768×768 패치의 위치만 바꾸는 반복 미리보기는 7.55→3.41ms였다. 이는 실시간 합성 추가 전의 투명 오버레이·변형 캐시 재사용 측정이며, 아래의 최종 합성 계산 시간은 포함하지 않는다. 화면 렌더링/OS 입력 지연, 전체 MapSet 처리, GPU 처리도 포함하지 않는다. 큰 사진의 첫 원본 해상도 회전은 여전히 GUI 스레드에서 실행되므로 별도 개선 대상이다.

환경은 Python 3.14.6 / PySide6 6.12.0 / NumPy 2.5.1 / OpenCV 5.0.0, OpenCV 스레드 32개다. 저장소의 권장 의존성 범위와 다른 현재 설치 환경이므로 권장 환경에서의 재검증이 필요하다. 변경 전 코드는 PySide6의 memoryview에 `setsize()`를 호출해 실패했다. baseline 측정에만 그 호출을 메모리에서 제거했으며, 다른 연산과 복사 비용은 유지했다. 현재 코드는 PySide6 buffer API를 사용한다.

## 검증 결과 및 남은 차이

- 새 기능·회귀·Qt 이벤트 테스트 22개 통과.
- 기존 패치 보관함·MapSet 편집 테스트를 더한 최종 검사: 30개 통과, 기존의 `fast_preview` 테스트 한 개 제외. 해당 테스트는 변경 전 HEAD에도 없는 인자를 호출하여 원래 실패한다. 최초 확장 실행의 결과는 29 통과/1 실패였다.
- 전체 수집은 기존 PyQt6/제거된 `PoissonApi` 및 training 모듈 참조 등의 문제로 23개 수집 오류가 발생했다. 전체 테스트 통과로 보고하지 않는다. 상세 출력은 `perf/test-collection.txt`.
- 실제 Qt 키보드·마우스 이벤트로 임시 이동, 크기 변경, 입력창 Undo, 패치 이동·확정·취소, 다각형 완료, UI 그룹 표시와 메뉴 상태를 검사했다.
- 화면은 offscreen 렌더링으로 확인했다. 실사용 이미지에 대한 사용자 평가나 Windows 실화면의 장시간 입력 테스트는 아직 수행하지 않았다.

## 실시간 합성 미리보기 추가 구현

패치를 배치한 뒤 이동·회전·크기를 바꾸거나 상단 Clone 모드를 선택하면 해당 모드의 원본 해상도 합성 결과가 비동기로 갱신된다. Normal, Mixed, Detail Preserve, Boundary Mixed, Hard Paste를 지원한다. `Apply Blend` 또는 Enter로 선택한 모드를 적용한다. 기존의 별도 ‘단순 붙여넣기’ 버튼은 선택 모드와 무관하게 Hard Paste를 적용하는 동작을 유지한다.

- `tools/patch_preview.py`: 한 작업만 계산하고 대기 요청은 최신 상태 하나로 교체한다. 위치·변형된 패치·합성 모드·map key·이미지 cacheKey·파일 경로를 요청에 묶는다. 취소·도구 전환 시 요청을 무효화한다. 작업 중 닫기에도 worker는 이미지 snapshot만 참조하며 QWidget/QPixmap에 접근하지 않는다.
- `service/editing_service.py`의 `compose_patch_mode`: 미리보기와 실제 `EditingWorker`가 동일한 합성 분기를 호출한다. Detail Preserve의 normal map 색상 보정 제외도 공통으로 처리한다.
- 대상 QImage snapshot을 worker에서 한 번 BGR로 변환해 위치 변경에 재사용한다. 원본 해상도로 합성한 결과 중 패치 사각 영역을 잘라 GUI에 전달한다. 이 영역 바깥을 변경하지 않는 현재 합성 함수의 계약을 픽셀 테스트로 확인했다.
- 계산 중에는 투명한 위치 안내와 ‘합성 계산 중’ 표시가 보이고, 완료 후에는 불투명한 최종 합성 픽셀과 ‘최종 합성 미리보기’ 표시로 바뀐다. 계산 실패는 명시적으로 표시한다. 큰 패치의 즉시 갱신이나 일정 프레임률을 보장하는 구현은 아니다.
- 미리보기는 현재 표시 중인 map만 계산한다. 적용은 기존처럼 MapSet 전체에 수행한다. 미리보기로 원본·Undo·수정 여부가 변경되지는 않는다. 합성 중 화면 배경도 실제 적용 입력인 확정 이미지로 표시하여 미적용 필터 미리보기와 섞이지 않게 했다.

추가 테스트 27개 통과: 5개 모드 × albedo/normal map × 원위치 경계/회전·확대 조합 20개에서 별도로 변형한 실제 적용 결과와 전체 이미지 픽셀이 일치했다. 나머지는 최신 요청 교체, 취소·닫기, 실패 복구, 계산 중 map 교체·canvas 삭제, 실제 Qt 키보드 이동 및 모드 변경을 검사했다. 기존 관련 검사까지 **57개 통과, 기존 `fast_preview` 인자 테스트 1개 제외**다. 전체 수집의 기존 오류는 위에 기재한 상태다.

UTF-8과 맑은 고딕으로 offscreen 렌더링한 화면은 `perf/live-blend-normal.png`, `perf/live-blend-mixed.png`, `perf/live-blend-detail-preserve.png`, `perf/live-blend-boundary-mixed.png`, `perf/live-blend-hard-paste.png`에 있다. Windows 실화면의 장시간 드래그 사용성 검증은 별도다.

## 힐링 브러시 추가 개선

이전에는 드래그 중 픽셀 미리보기가 없었고, 마우스를 놓으면 작은 원을 경로에 반복 배치해 각각 Poisson 합성을 수행했다. 불투명도도 원마다 누적되어 마우스 이벤트 밀도에 따라 결과가 달라질 수 있었다.

- 한 획을 둥근 선분들의 합집합 마스크로 만들고 **미리보기 요청 하나당 한 번, 최종 적용 시 map마다 한 번** Poisson 합성한다. 불투명도는 한 획에 한 번 적용한다. 여러 번 덧칠하려면 획을 끝낸 뒤 다시 그린다. 샘플과 대상의 공통 유효 범위로 마스크를 잘라 이미지 바깥을 읽거나 반대편 픽셀을 가져오지 않는다.
- `tools/healing_preview.py`의 전용 serial worker가 원본 이미지와 획 시작 시 크기·불투명도를 고정하여 처리한다. 드래그 중에는 현재 획만 미리 보고, 마우스를 놓으면 동일한 `apply_healing_strokes` 함수로 MapSet 전체 또는 단일 이미지에 적용한다. 입력 이미지가 바뀌면 이전 결과를 폐기한다.
- 한 작업이 실행되는 동안 대기 요청은 최신 누적 경로 하나로 교체한다. 같은 획의 이전 부분 계산이 먼저 끝나면 진행 중 표시로 보여 주고, 최신 경로가 완료되면 최종 합성 미리보기로 표시한다. 새로운 획이나 취소된 획의 결과가 섞이지 않도록 세션 identity로 검사한다.
- Alt+클릭(기존 Ctrl+클릭도 유지)로 샘플을 지정한다. 청록색 샘플 원은 드래그 중 실제 채취 위치를 따라간다. `[`/`]`로 크기를 조정하고, 진행 중 획은 Esc·도구 전환·포커스 이탈·이미지 변경으로 취소한다.
- 취소와 미리보기는 원본·Undo·수정 여부를 건드리지 않는다. 성공한 한 획만 Undo 한 단계로 남는다. 유효한 샘플 영역이 없거나 불투명도가 0이면 수정 상태를 만들지 않는다. 적용 중 다음 획은 시작하지 않으며, 적용 중 대상이 바뀌거나 편집되면 오래된 결과로 덮어쓰지 않는다.
- 화면상의 최신 편집 픽셀을 최종 적용 입력으로 사용하도록 고쳤다. 기존에는 저장된 편집 사본 또는 파일을 읽어 현재 canvas와 어긋날 여지가 있었다. 단일 이미지만 열린 경우 실제 합성 없이 수정 상태만 올리던 경로도 제거하고 비동기 적용을 연결했다.

힐링 새 테스트 **24개 통과**, 기존 관련 검사 포함 **81개 통과, 기존 `fast_preview` 인자 테스트 1개 제외**다. 입력 이벤트가 많은 직선과 적은 직선의 픽셀 일치·한 번의 solve·불투명도 일관성, 클릭/드래그/샘플 경계에서 미리보기와 EditingWorker의 픽셀 일치, MapSet 전체 적용과 Undo, 단일 이미지 Undo/Redo, 취소·변경된 이미지·실패·창 삭제를 검사했다.

한글 offscreen 화면은 `perf/healing-before.png`와 `perf/healing-live-preview.png`다. 화면 최초 표시에서 Qt eventFilter의 기본 메서드가 native receiver를 다시 전달받으며 타입 오류를 내는 현상도 재현했다. 앱 단축키 필터가 처리하지 않는 이벤트는 `False`로 통과시키도록 수정했고, 이후 캡처 3회와 전체 관련 테스트가 정상 완료됐다. 긴 획·큰 이미지에서는 계산 완료까지 지연이 있을 수 있고, Windows 실화면의 장시간 드래그 검증은 아직 수행하지 않았다.

우선순위가 높은 후속 차이는 다음과 같다.

1. **일반 브러시의 미리보기와 최종 결과 일치:** 힐링은 해결했지만 일반 브러시의 Qt 선 그리기와 OpenCV 스트로크 재생은 경계 및 겹친 불투명도 처리 방식이 다르다. 일반 브러시도 한 획의 coverage를 한 번 누적하고 동일한 합성 규칙으로 미리보기와 MapSet 재생을 처리하는 방향이 적합하다.
2. **색상 적응과 형태 보존의 분리:** PhotoCraft에는 structure/color 별도 제어가 있다. Dataset Studio의 Detail Preserve와 Boundary Mixed도 결함 중심 보존·경계 폭·색상 적응을 분리해 실제 결함 샘플로 평가할 필요가 있다. 일반 이미지의 자연스러움만으로 결함을 약화시키면 안 된다.
3. **Normal map 의미 보존:** 색 보정 제외만으로 충분하지 않다. 회전 시 방향 성분, 합성 시 벡터 정규화를 별도로 설계해야 한다. 현재 변경은 이 문제를 해결했다고 주장하지 않는다.
4. **패치 변형 핸들:** 현재는 좌클릭 이동·우클릭 회전·상단 버튼·오른쪽 수치 입력이다. 화면상의 크기/회전 핸들과 Shift 각도 스냅이 다음으로 유용하다. 원근 변형은 라벨/다중 map 동기화 계약을 먼저 정해야 한다.
